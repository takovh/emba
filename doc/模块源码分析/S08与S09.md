

## `S08与S09`

**S08_main_package_sbom**

 核心职责： 软件物料清单（SBOM）的中央调度器，通过包管理器识别固件中已安装的软件包。

  工作流程：
  1. 从 `modules/S08_main_package_sbom_modules/` 动态加载子模块（Debian、OpenWrt、RPM 等各发行版的包解析器）
  2. 并行或串行执行 `S08_MODULES_ARR` 中的各子模块，每个子模块解析各自格式的包管理器数据库（如 `dpkg/status`、`opkg/status`）
  3. 所有子模块完成后，调用 `build_dependency_tree()` 构建 SBOM 依赖树：
    - 读取每个 SBOM JSON 组件文件
    - 通过 `jq` 提取 `dependency` 属性，解析组件间依赖关系
    - 用 `jo` 输出标准化的依赖 JSON，最终汇总到 `SBOM_dependencies.txt`

  提供的工具函数：
  - `clean_package_details()` / `clean_package_versions()` — 清洗包名和版本字符串，供子模块调用
  - `build_cpe_identifier()` / `build_generic_purl()` — 生成 CPE 和 PURL 标识符


**S09_firmware_base_version_check**

核心职责： 静态二进制版本扫描，对不受包管理器管理的二进制文件识别版本信息，补充 S08 的盲区。

  工作流程：
  1. 文件筛选（与 S08 联动）： 若 S08 已运行，先从 `dpkg/opkg` 的文件列表中提取已知路径，再对 `P99_CSV_LOG`（全量二进制清单）做 diff，只保留包管理器未覆盖的文件
  2. 预生成字符串： 对筛选后的二进制文件并行运行 strings 命令，结果缓存到 `strings_bins/strings_<md5>_<name>.txt`
  3. 版本规则匹配： 加载 `config/bin_version_identifiers/*.json` 中约 200 条规则，每条规则支持三种匹配模式：
    - `normal` — 对所有二进制的 strings 输出跑正则
    - `strict` — 只对 `affected_paths` 指定路径的 ELF 文件匹配
    - `zgrep` — 对压缩文件直接用 `zgrep` 匹配
  4. 去重优化： 一旦某规则已命中，跳过该规则的后续测试；包管理器已知的包名直接跳过对应规则
  5. 结果写入： 通过 `version_parsing_logging()` 提取版本字符串、构建 CPE/PURL，写入 `S08/S09` 的 CSV 日志和 SBOM JSON


**两者关系**

  S08（包管理器 SBOM）→ 产出已知包列表
           ↓
  S09 用该列表排除已识别的文件，只对"漏网之鱼"做字符串版本扫描
           ↓
  共同输出到 S08_CSV_LOG，汇总为完整 SBOM

  S08 精准但依赖包管理器数据库；S09 覆盖面广但基于启发式规则，两者互补。
